# 0.5.2 — 2026-09-25

## Added

- **`authority`, `sourceNote`, and `notes`** on whole-part `regulations_get_cfr_section` reads, and `authority` / `sourceNote` on each `sections[]` entry whose subpart or subject group states its own. Single-section and appendix reads carry none [#52](https://github.com/cyanheads/federal-regulations-mcp-server/issues/52).
- **Cite-form `section` and `part` inputs** on `regulations_get_cfr_section` and the `regulations://cfr/{title}/{part}/{section}` resource: `section` takes the `cfrCite` the server returns (`"40 CFR 141.61"`, `"40 C.F.R. 141.61"`, `"14 CFR 241 § 25"`) and `part` takes `"Part 141"`; `notice` names each rewrite [#53](https://github.com/cyanheads/federal-regulations-mcp-server/issues/53).
- **`conflicting_title`** (`ValidationError`) when a `section` cite names another title (`"21 CFR 141.61"` with `title: 40`), which answered `not_found` before.

## Changed

- **`bodyText` renders inline markup**: superscripts `^x` and subscripts `_x` (`3 × 10^−8`, `CO_{2}e`), footnote markers `[n]`, `<AC>` diacritics and `<E T="7503">` overlines as combining marks (`x̄`, `R̅M̅`), no stray space after an inline element, and a section's own `<SECAUTH>` / `<APPRO>` kept [#51](https://github.com/cyanheads/federal-regulations-mcp-server/issues/51), [#60](https://github.com/cyanheads/federal-regulations-mcp-server/issues/60). `bodyTextLength`, `bodyTextNextOffset`, and `sections[].offset` values saved from 0.5.1 no longer line up.
- **Whole-part `heading`** is the part's own (`PART 141—NATIONAL PRIMARY DRINKING WATER REGULATIONS`), not `Part 141`.
- **Mirror `INGEST_VERSION` 3 → 4**: an existing mirror reads as stale and every read goes live until `bun run mirror:refresh` re-derives each held title.
- **Mirror freshness is per title**: current section reads and mirror searches use a title only while its `cfr_part_index.issue_date` is at eCFR's latest issue, and read it live otherwise. On a ready mirror these reads now need eCFR's titles document and fail `upstream_unavailable` when it can't be read [#55](https://github.com/cyanheads/federal-regulations-mcp-server/issues/55).
- **`regulations_browse_cfr` search** reports `date` on mirror results too: the titles document's index date.
- **`regulations_browse_cfr` structure mode** holds each title's parsed structure document by title and date (4 entries, 15 minutes), so paging a part costs one upstream read [#44](https://github.com/cyanheads/federal-regulations-mcp-server/issues/44).

## Fixed

- **XML tag stripping, block extraction, and `isCompleteXmlDocument`** run in linear time on unclosed openers [#57](https://github.com/cyanheads/federal-regulations-mcp-server/issues/57), [#62](https://github.com/cyanheads/federal-regulations-mcp-server/issues/62). A literal `<` in a search excerpt now survives (`systems <500 service connections`).
- **Structure-mode `cfrCite` for dotless sections** names the part (`14 CFR 241 § 01`, not `14 CFR 01`) [#59](https://github.com/cyanheads/federal-regulations-mcp-server/issues/59).
- **Mirror ingest** writes a title's part index only after its section rows commit, so an aborted run never dates older rows as current.
