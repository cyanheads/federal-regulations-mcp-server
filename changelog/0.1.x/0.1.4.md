# 0.1.4 — 2026-08-09

## Added

- **`regulations_browse_cfr` `part`** — now filters search mode too (`hierarchy[part]` on the live path, an equality filter on the mirror), requiring `title` in either mode via a new `title_required_for_part` error; part values are matched exactly after stripping a spelled-out `Part ` prefix and surrounding whitespace. ([#7](https://github.com/cyanheads/federal-regulations-mcp-server/issues/7))
- **`regulations_browse_cfr` search hits** — `hierarchyPath` now pairs a live hit's part label with the name eCFR returns beside it (e.g. `Part 51 — Requirements for Preparation, Adoption, and Submittal of Implementation Plans`); mirror hits stay structural, since the index stores no level names. ([#8](https://github.com/cyanheads/federal-regulations-mcp-server/issues/8))

## Fixed

- **`regulations_find_comments`** — rejects calls supplying more than one of `docket_id` / `document_object_id` / `fr_document_number` / `comment_id` with a new `multiple_targets` error, instead of silently reading `comment_id` and dropping the rest; an empty string still counts as absent. ([#3](https://github.com/cyanheads/federal-regulations-mcp-server/issues/3))
- **`RegulationsGovService`** — the 400 Regulations.gov returns for an ID it cannot parse (`"Invalid ID: …"`) now maps to the same `not_found` path as a 404, discriminated on the response body so other 400s (bad filter name, bad page size) keep their `InvalidParams` classification. ([#5](https://github.com/cyanheads/federal-regulations-mcp-server/issues/5))
