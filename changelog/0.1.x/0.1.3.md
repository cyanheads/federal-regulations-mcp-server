# 0.1.3 — 2026-08-09

## Changed

- **`regulations_browse_cfr` search-mode `date`** — now forwarded to eCFR's `date` parameter; an undated query pins to eCFR's current index date instead of matching every historical version of a section alongside its current text. Out-of-range dates raise `date_out_of_range` (`InvalidParams`) naming the indexed window (`2017-01-03` through the current index date). ([#1](https://github.com/cyanheads/federal-regulations-mcp-server/issues/1))
- **`regulations_browse_cfr` title-scoped search** — sends `hierarchy[title]` instead of the upstream-rejected `conditions[title]`. ([#1](https://github.com/cyanheads/federal-regulations-mcp-server/issues/1))
- **Search result `heading`** — now taken from eCFR's `headings` map (the node's name) rather than `hierarchy_headings` (its structural label); appendix hits, which carry no `hierarchy.section`, are identified via `hierarchy.appendix` and no longer fall through to `(untitled)`. ([#1](https://github.com/cyanheads/federal-regulations-mcp-server/issues/1))
- **eCFR mirror search routing** — a scoped mirror (`ECFR_MIRROR_TITLES`) now answers a search only when the requested title is in its indexed set, and never answers an all-titles query unless the index is complete; everything else falls through to live eCFR instead of returning a false empty result from a corpus that never held the answer. Coverage is read from a new `cfr_mirror_meta` table written at sync time, not from the environment the server happens to boot with. ([#2](https://github.com/cyanheads/federal-regulations-mcp-server/issues/2))
- **`regulations_browse_cfr` output** — every search result now carries `sourceScope`, naming which corpus answered (mirror titles, or the live index and its date); the empty-result `notice` names it too, so a zero-match search is never mistaken for "no such regulation." `mirror:verify` prints the same coverage.
- **`no_results` error contracts removed** — `regulations_search_rules`, `regulations_list_open_comments`, and `regulations_browse_cfr` no longer declare a `no_results` reason; a zero-match query is a successful empty result with a `notice`, not a domain error, on all three. ([#4](https://github.com/cyanheads/federal-regulations-mcp-server/issues/4))

## Added

- **Socket install scanner** — `@socketsecurity/bun-security-scanner` wired through `bunfig.toml`; scans every package before install for malware, typosquats, and CVEs.
- **`minimumReleaseAge` supply-chain guard** — `bunfig.toml` blocks package versions published less than 3 days ago, with `@cyanheads/mcp-ts-core` excluded for same-day framework adoption.
- **MCPB native-binding strip** — `scripts/clean-mcpb.ts` and `scripts/lint-packaging.ts` now also strip/reject platform-specific native bindings (`@duckdb/node-bindings-*`) from packed bundles, alongside the existing agent-doc strip, so a DataCanvas-enabled server's `.mcpb` stays portable and under the registry size cap.
- **`.github/SECURITY.md`, `.github/FUNDING.yml`, `.gitattributes`** — template files the project was missing.

## Fixed

- **Dockerfile** — pinned the `oven/bun` base image to `1.3.14` (was floating `1.3`), added BuildKit cache mounts on every `bun install`/`bun add` layer, and switched the OTel peer-dependency install to `--omit=dev --ignore-scripts`.
