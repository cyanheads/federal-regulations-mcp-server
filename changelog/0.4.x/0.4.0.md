# 0.4.0 — 2026-09-22

## Changed

- **`regulations_get_cfr_section` `bodyText`** is now one bounded, resumable window instead of the whole location's text: new `offset`/`max_chars` inputs, required `bodyTextOffset`/`bodyTextLength` outputs, and `bodyTextNextOffset` while text remains. A whole-part fetch's `sections[]` drops per-section `bodyText` — it's now a text-free index (`section`, `heading`, `cfrCite`, `offset`) cut to the window. The `regulations://cfr/{title}/{part}/{section}` resource returns the default 64,000-character window on the same fields [#29](https://github.com/cyanheads/federal-regulations-mcp-server/issues/29).
- **`regulations_browse_cfr` structure mode with `part`** now returns the part's sections and appendices flattened and paged (`page`/`per_page`), each naming its `subpart`/`subjectGroup`, instead of the part's direct children — mostly subparts and subject groups, which carry no read path [#31](https://github.com/cyanheads/federal-regulations-mcp-server/issues/31).
- **`regulations_browse_cfr` search mode** collapses eCFR's per-version repeats to one row per section. `totalCount` now describes what `countBasis` says it counts (`sections`, or eCFR's own `section_versions` until the whole hit list is read), not the raw versioned hit count [#42](https://github.com/cyanheads/federal-regulations-mcp-server/issues/42).
- **A `date` past eCFR's up-to-date date** now answers `date_out_of_range` (naming the window) instead of `not_found`, on `regulations_get_cfr_section` and `regulations_browse_cfr` structure mode; `date` on every eCFR tool must now be a real calendar day (`2025-02-30` is rejected at input validation, not just the `YYYY-MM-DD` shape) [#35](https://github.com/cyanheads/federal-regulations-mcp-server/issues/35).
- **`ECFR_MIRROR_REFRESH_CRON`** has no default — unset now registers no refresh job, where it previously defaulted to a weekly cron that never actually ran [#26](https://github.com/cyanheads/federal-regulations-mcp-server/issues/26).
- **Structure labels and descriptions** are reduced to plain text — eCFR's inline `<em>`/`<sub>`/`<span>` markup is stripped and named/numeric entities decoded rather than passed through; search headings, paths, and excerpts, already tag-stripped, now decode entities too [#31](https://github.com/cyanheads/federal-regulations-mcp-server/issues/31).

## Added

- **`regulations_get_cfr_section` `section`** now resolves a cite the way people write it — `"61"` in part 141, a leading `§`/`Sec.`, and a paragraph cite (`"141.61(c)"`, which returns the whole section) — before falling back to `not_found`; the resolved identifier comes back in `section`/`cfrCite` with a `notice`, and the cfr-section resource resolves the same inputs [#22](https://github.com/cyanheads/federal-regulations-mcp-server/issues/22).
- **`regulations_browse_cfr` `page`** input pages both search results and a part's structure listing; a live search page starting past eCFR's 10,000-hit window fails as `page_out_of_window` [#30](https://github.com/cyanheads/federal-regulations-mcp-server/issues/30).

## Fixed

- **The eCFR mirror refresh cron never ran** — `node-cron` is an optional peer of the framework that the server never declared, so it was never installed and `schedulerService.schedule()` always rejected. It's now a regular dependency, and a tick against a mirror that has never finished `mirror:init` is skipped with a log line instead of becoming a full in-process build [#26](https://github.com/cyanheads/federal-regulations-mcp-server/issues/26).

## Dependencies

- `node-cron` added: `^4.6.0` (regular dependency; previously an undeclared optional framework peer).
