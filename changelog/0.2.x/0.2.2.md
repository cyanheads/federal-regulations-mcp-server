# 0.2.2 — 2026-08-09

## Fixed

- **`upstream_unavailable` (connect-level)** — a DNS failure or refused connection against Regulations.gov now classifies as `upstream_unavailable` with the tool's recovery hint via a new `fetchUpstream` wrapper, instead of a bare `InternalError` with no reason. `regulations_get_document` and the eCFR tools were unaffected — they already route through `fetchWithTimeout`. ([#15](https://github.com/cyanheads/federal-regulations-mcp-server/issues/15))
- **`auth_required`** — a Regulations.gov API key rejected by the upstream (HTTP 401 or 403) now raises `auth_required` as `Unauthorized`, the same code and recovery hint a missing key gets, instead of a bare `Forbidden` with no reason. ([#16](https://github.com/cyanheads/federal-regulations-mcp-server/issues/16))
- **`rate_limited`** — the 429 branch now carries the tool's declared recovery hint, appending the upstream's `Retry-After` wait when one is sent; previously the reason reached the wire with no hint and no `Recovery:` line. ([#17](https://github.com/cyanheads/federal-regulations-mcp-server/issues/17))
- **`upstream_unavailable` (5xx)** — a 500 or 501 from any of the three upstream services now classifies and retries as `upstream_unavailable`, matching the rest of the 5xx range; previously the two commonest 5xx statuses fell straight to `InternalError` with no reason and no retry. A retried 5xx now takes a few seconds to report instead of failing immediately. Also covers `EcfrService.currentDate`'s missing-index-date failure and a failed Federal Register document-body fetch (`include_full_text`), which previously read as `NotFound`. ([#18](https://github.com/cyanheads/federal-regulations-mcp-server/issues/18))
- **eCFR mirror sync** — the sync `Context` shim now stubs `recoveryFor`, so an eCFR transport failure mid-sync (`mirror:init`, `mirror:refresh`, the HTTP refresh cron) surfaces its classified `ServiceUnavailable` instead of `TypeError: ctx.recoveryFor is not a function`. ([#19](https://github.com/cyanheads/federal-regulations-mcp-server/issues/19))
