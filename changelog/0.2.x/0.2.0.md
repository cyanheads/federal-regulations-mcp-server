# 0.2.0 — 2026-08-10

## Added

- **`regulations_get_cfr_section` `appendix` input** — reads one CFR appendix by its verbatim identifier (`title` + `appendix`, `part` optional but disambiguating); adds `appendix` and `appendices` (a whole-part read's un-inlined appendix identifiers + headings) to the output, plus `location_required` and `conflicting_target` error reasons. ([#6](https://github.com/cyanheads/federal-regulations-mcp-server/issues/6))
- **`regulations_browse_cfr`** — structure nodes and search hits carry an `appendix` field; an appendix's `cfrCite` now names the appendix itself, not the part around it. ([#6](https://github.com/cyanheads/federal-regulations-mcp-server/issues/6))
- **`mirror:verify`** — reports whether the index was written by the current ingester, naming `mirror:refresh` as the fix when it wasn't. ([#9](https://github.com/cyanheads/federal-regulations-mcp-server/issues/9))

## Changed

- **`regulations_get_cfr_section` `part`** — input is now optional (required unless `appendix` is given); output `part` is nullable. **Breaking**: a caller assuming `part` is always a non-null string must now handle `null` (an appendix hanging off a chapter, subchapter, or subtitle rather than a part).
- **CFR cites** — a section or appendix cite now names its enclosing part explicitly when the section number doesn't embed it (`14 CFR 241 § 25`, not `14 CFR 25`), applied uniformly to live hits, mirror hits, the read tool, and the `regulations://cfr/{title}/{part}/{section}` resource. ([#9](https://github.com/cyanheads/federal-regulations-mcp-server/issues/9))
- **eCFR body-text extraction** — keeps `<HD1>`–`<HD7>` subheadings, `<TABLE>` rows (pipe-delimited), the flush-paragraph family (`<FP-1>`, `<FP1-2>`), and an editorial note's `<HED>`/`<PSPACE>`, for sections and appendices alike; previously only `<P>`/`<FP>` paragraphs were kept, which answered 61% of appendix nodes in a sample with an empty body. ([#6](https://github.com/cyanheads/federal-regulations-mcp-server/issues/6))

## Fixed

- **eCFR mirror ingest** — a section's part now comes from its enclosing `<DIV5 TYPE="PART">` element instead of the section number cut at its first dot; a part with dotless section identifiers (14 CFR 241: `Section 25`, `Sec. 1-1`) was filing rows under a part named after the section number, so a scoped search or cite could return an unrelated regulation's text. ([#9](https://github.com/cyanheads/federal-regulations-mcp-server/issues/9))
- **Mirror ingest versioning** — the ingester now stamps an `ingest_version`; rows from a superseded ingester are treated as not ready (every read falls back to live eCFR until `mirror:refresh` re-derives them), and a refresh tombstones rows it no longer writes so corrected or withdrawn rows don't survive beside the fix. ([#9](https://github.com/cyanheads/federal-regulations-mcp-server/issues/9))
- **`mirror:verify`** — its sample query was passing its result limit into the `part` filter added in 0.1.4, leaving the limit unset. ([#9](https://github.com/cyanheads/federal-regulations-mcp-server/issues/9))
- **XML paragraph parsing** — a malformed `<FP-1>`/`<FP-2>` closing-tag match could swallow up to 257 KB of content, every paragraph and subheading up to the next plain `</FP>` in the document. ([#6](https://github.com/cyanheads/federal-regulations-mcp-server/issues/6))
