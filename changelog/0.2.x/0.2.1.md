# 0.2.1 — 2026-08-10

## Changed

- **`regulations_get_cfr_section` `bodyText`** — carries the trailing `<CITA>` Federal Register source citation and `[Figure: /graphics/…]` references now, in document order; previously dropped entirely. Measured across four whole CFR titles (2,994 sections, 143 appendices): section bodies grew 1.48% in total (mean +37 characters, 41% of sections affected), appendix bodies grew 6.4%, and the 77 appendices in the sample that read back blank dropped to zero — empty `bodyText` is now reserved for a true `[Reserved]` placeholder. **eCFR mirror `INGEST_VERSION` moves to 3** for this change: an existing local mirror is treated as stale until `bun run mirror:refresh` re-derives it, and reads fall back to live eCFR in the meantime. ([#13](https://github.com/cyanheads/federal-regulations-mcp-server/issues/13))

## Fixed

- **`regulations_get_cfr_section` / `regulations://cfr/{title}/{part}/{section}`** — a nonexistent section, whole part, or resource cite now raises the declared `not_found` reason with its recovery hint (verify via `regulations_browse_cfr` structure mode), instead of a bare message with a null `data.reason`. ([#11](https://github.com/cyanheads/federal-regulations-mcp-server/issues/11))
- **`upstream_unavailable`** — every tool and resource that declares it now raises it: a transport failure (5xx, timeout, HTML error page) surviving retry is stamped with the reason and the definition's own recovery hint via a shared `withUpstreamReason` helper, instead of reaching the caller with a null `data.reason`. Also newly attached: `regulations_get_document` `not_found` on a Federal Register 404, and `regulations_browse_cfr` `title_not_found` now also covers a title the versioner publishes no structure tree for at all (a reserved title, or a date outside its coverage), not only a missing part. ([#14](https://github.com/cyanheads/federal-regulations-mcp-server/issues/14))
- **eCFR mirror sync** — a title document that arrives truncated (a dropped stream, a proxy serving the first N bytes with a 200) is now detected via `isCompleteXmlDocument` and left untouched, rather than having every section past the cut tombstoned as withdrawn; the run previously reported `complete` over a silently gutted title. ([#12](https://github.com/cyanheads/federal-regulations-mcp-server/issues/12))
- **`scripts/` and `tests/`** — no longer exempt from the TypeScript gate: `tsconfig.json` `include` widens to `["src/**/*", "scripts/**/*", "tests/**/*"]` (`tsconfig.build.json` keeps its own narrower `include: ["src/**/*"]`, so `dist/` output is unchanged). Fixed the 99 errors the widened check surfaced, including a `HandlerContext<Reason>` mismatch across contract-declaring tool tests, now centralized in `tests/helpers/handler-context.ts`, and a dead framework-only import branch in `scripts/lint-mcp.ts`. ([#10](https://github.com/cyanheads/federal-regulations-mcp-server/issues/10))
